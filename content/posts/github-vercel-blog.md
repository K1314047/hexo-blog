## 第一部分，先把本地项目跑起来

任何网站上线之前，第一步一定是在本地确认它能正常运行。

## 第二部分，第一次上传 GitHub

把代码提交到 GitHub 仓库之后，你就有了一个可以持续维护的版本基线。

## 第三部分，连接 Vercel 部署上线

将 GitHub 仓库接入 Vercel 后，每次 push 都可以自动触发构建和部署。

## 第四部分，部署时遇到的真实问题

最常见的问题通常集中在依赖版本、环境变量和静态资源路径。

## 第五部分，上线之后继续改版

网站第一次成功上线之后，并不代表工作结束了，反而是优化体验的开始。

## 第六部分，第二次上传其实很简单

只要本地调试通过，后续维护其实会越来越顺手。
